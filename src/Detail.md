# `src` 目录详解

## 这一层在做什么

`src/` 是项目源码总入口。它的职责不是具体实现某个功能点，而是把“可编译源码”和“可打包资源”统一放进 Gradle 约定的标准源集结构里。

在 Gradle Java 项目中，`src/main/...` 本身就是一种约定式接口：

- `src/main/java/` 里的内容会被 Java 编译器编译成 `.class`。
- `src/main/resources/` 里的内容会被原样复制进资源输出目录，再一起打包进 jar/zip。

因此，`src/` 是“构建输入层”。

## 为什么这一层重要

模组的实际行为当然由类和资源决定，但如果这些文件不放在 Gradle 能理解的标准位置，构建脚本就要写更多手动配置。当前项目没有额外声明 `sourceSets`，说明它完全依赖标准目录布局。

这带来几个效果：

- 结构清晰，任何熟悉 Gradle 的维护者都能快速定位代码。
- `build.gradle` 保持简洁，没有额外路径映射负担。
- Java 代码与资源天然分层，避免把本地化文本硬编码进类中。

## 当前目录的下一级

- `main/`：主源集。当前项目没有 `test/`，说明作者暂时没有为这个模组维护自动化单元测试层。

## 与其他层级的关系

- 与根目录：根目录的 `build.gradle` 会把这里当作主要输入。
- 与 `src/main/java/`：这里承接真正的逻辑实现。
- 与 `src/main/resources/`：这里承接所有用户可见文本资源。
- 与 `dist/`：`src/` 中的内容经过编译和打包后，最终进入发布物。

## 从工程流角度看这一层

可以把 `src/` 理解为“素材仓”：

- Java 类提供行为。
- resource 文件提供文本与静态资源。
- Gradle 负责把两者合并成 Mindustry 可加载模组。

因此，它是整个项目从静态文件到运行模块的起点。
