# `src/main` 目录详解

## 这一层在做什么

`src/main/` 代表 Gradle Java 项目的“主源集”。这个层级的职责非常明确：定义模组正式发布时会被打进最终产物的所有源文件。

在当前仓库中，这一层分成两个平行子层：

- `java/`：行为实现层。
- `resources/`：运行时资源层。

这不是普通分类，而是构建语义上的分类。Gradle 对这两个目录的处理方式完全不同：

- Java 源码要先编译。
- 资源文件不编译，但会被复制进输出目录。

## 为什么只有 `main`

项目当前没有 `src/test/`、`src/android/`、`src/client/` 等额外源集，说明作者选择了最小结构：

- 功能逻辑全在主源集里。
- Android 兼容不是通过单独源码分支处理，而是通过构建时生成 `classes.dex` 解决。

这和 `build.gradle` 的方案是统一的：代码只写一份，通过不同打包任务适配不同运行环境。

## 这一层的实现意义

把 `java` 和 `resources` 分开有几个直接好处：

- 代码里不必硬编码 UI 文案，减少维护成本。
- 中英文 bundle 可以按 Mindustry 资源机制自动装载。
- 构建时资源可以无损进入 jar/zip，代码则可以独立编译和 dex 化。

## 与其他层级的关系

- 上层 `src/`：把这里当作“主源集根”。
- 下层 `java/`：提供入口类、功能类、更新检查类。
- 下层 `resources/`：提供设置菜单名称、筛选对话框标题、提示词等。
- 根目录 `mod.json`：最终会引用 `java/` 中编译出的主类作为入口。

## 这一层在运行链路中的位置

从运行路径上看：

1. 构建时，`src/main/java/` 被编译。
2. 构建时，`src/main/resources/` 被复制。
3. 两者一起被打入 merged jar/zip。
4. 游戏启动时通过 `mod.json` 找到入口类。
5. 入口类再在运行时读取 bundle 和设置项。

所以 `src/main/` 不是单纯的文件夹，而是“运行时模块内容”的正式来源。
