# `src/main/java/betterminimap/features` 目录详解

## 这一层在做什么

这是整个模组最核心的功能实现层。当前只有一个文件 `BetterMiniMapFeature.java`，但它实际上承载了以下几类工作：

- 设置项定义。
- 过滤器状态初始化和缓存。
- 小地图叠加层挂接。
- 可见单位/建筑收集。
- 单位聚合计算。
- 小地图图标绘制。
- 单位/建筑筛选对话框 UI。

也就是说，真正让 betterMiniMap 成为 betterMiniMap 的逻辑，几乎都在这一层。

## 整体设计思路

### 1. 用静态单例式结构管理整个功能

类里几乎全部是 `static` 字段和方法。这意味着作者把“小地图增强功能”看成一个全局模块，而不是可以实例化多份的对象。对 Mindustry 客户端模组来说，这种设计很符合实际：

- 游戏里通常只有一套 HUD。
- 小地图叠加层只需要存在一份。
- 设置项也只需要一份。

### 2. 通过缓存和定时刷新降低开销

这个类非常明显地重视性能，而不是每帧暴力重算：

- 用 `Interval` 控制不同刷新频率。
- 设置读取不是每帧做，而是每 0.5 秒刷新一次。
- 叠加层挂接不是每帧重建，而是每 1 秒检查一次。
- 可见单位/建筑缓存不是每帧重建，而是每 0.25 秒更新一次。
- 单位聚合结果还额外依赖 `visibleRevision` 和 `clusteredWorld` 做缓存失效判断。

这和仓库约束“变更优先聚焦性能与可读性”是吻合的。

## 设置系统是怎么实现的

`buildSettings(SettingsTable table)` 是整个设置层入口。它做了三类事：

### 布尔开关

- 是否启用叠加层。
- 是否显示单位。
- 是否显示建筑。
- 是否显示敌方/友方单位。
- 是否显示敌方/友方建筑。
- 建筑底色是否按队伍染色。
- 是否检查更新。
- 是否弹出更新对话框。

### 数值滑条

- 单位图标缩放。
- 单位透明度。
- 单位聚合像素阈值。
- 建筑图标缩放。
- 建筑图标透明度。
- 建筑底色透明度。

### 自定义按钮项

通过自定义 `Setting` 对象插入两个按钮：

- 打开单位筛选对话框。
- 打开建筑筛选对话框。

这说明作者没有把所有配置压成简单 `checkPref` / `sliderPref`，而是在必要时扩展了交互层。

## 默认筛选状态是怎么初始化的

`ensureDefaultFilterLists()` 是这个文件里一个很关键但容易忽视的方法。

它的策略是：

- 第一次初始化时，把全部单位默认加入显示名单。
- 建筑默认列表则初始化为空 JSON 列表。
- 最后写入 `keyFilterInit`，避免重复初始化覆盖用户设置。

这意味着项目对单位和建筑采用了不同默认哲学：

- 单位默认全开，因为单位标记是这个模组的主卖点。
- 建筑默认空列表，说明作者不想让建筑图标一开始就过度挤占小地图。

## 可见对象缓存是怎么实现的

`rebuildVisibleCache(Rect viewRect)` 负责把“世界中的全部单位/建筑”压缩成“当前小地图视窗内、且符合设置条件的对象”。

筛选链路非常明确：

### 单位

1. 模组必须启用。
2. 单位显示必须启用。
3. `unitEnabledById` 中对应单位类型必须为真。
4. 根据玩家队伍判断敌我，再应用敌我显示设置。
5. 对象坐标必须落在 `viewRect` 内。

### 建筑

1. 模组必须启用。
2. 建筑显示必须启用。
3. `blockEnabledById` 中对应方块类型必须为真。
4. 敌我过滤通过。
5. 坐标必须落在 `viewRect` 内。

这一步非常重要，因为它把后续绘制负担控制在“局部可见对象”上，而不是全图。

## 单位聚合是怎么做的

`buildUnitClusters(float minimapScale)` 实现了 README 里最关键的“智能聚合”。

### 聚合阈值不是固定世界距离

代码把用户设置的 `unitClusterPx` 先换算成世界坐标距离：

- `clusterWorld = unitClusterPx / minimapScale`

这意味着缩放越大，屏幕上同样像素距离对应的世界距离越小；缩放越小，对应的世界距离越大。结果就是：

- 用户感知到的聚合尺度稳定。
- 聚合行为与小地图实际视觉密度绑定，而不是死板绑到地图坐标。

### 聚合条件

一个单位只能并入：

- 同 `UnitType`
- 同 `Team`
- 与当前聚合中心距离不超过阈值

这保证聚合结果在视觉上仍然有语义：

- 不同单位种类不会混成一个图标。
- 敌我不会混成一个图标。

### 聚合中心与朝向

`UnitCluster.add(Unit u)` 做了三件事：

- 用增量平均更新聚合中心坐标。
- 用方向向量求和累积总体朝向。
- 记录最后一个旋转值作为回退值。

这比简单取第一个单位的旋转更合理，因为群体移动时整体朝向更接近向量平均。

## 绘制层是怎么实现的

真正绘制发生在 `HudMinimapOverlay.draw()` 和 `drawMarkers()`。

### 叠加层挂接

`ensureOverlayAttached()` 会去 HUD 里找名为 `minimap` 的 `Table`，然后把一个自定义 `HudMinimapOverlay` 作为子元素插进去。

这种做法的优点：

- 不替换原版小地图，只是在上面叠一层。
- 原版小地图的布局和交互基础仍然保留。
- 叠加层可通过 `touchable = disabled` 避免拦截操作。

### 坐标变换

`HudMinimapOverlay.draw()` 中先算 `viewRect`，再建立变换矩阵：

- 把控件坐标系平移到 overlay 的屏幕位置。
- 按实际缩放比缩放到小地图控件大小。
- 再把世界坐标映射进当前视口。
- 最后加上半格 `tilesize / 2` 修正，让图标更贴近格中心。

这段矩阵代码是连接“世界对象坐标”和“HUD 上的小地图像素坐标”的关键桥梁。

### 单位绘制

`drawUnitCluster` 的视觉分三层：

- 半透明圆形底。
- 真实单位 `uiIcon`，按朝向旋转。
- 黑色细圆环描边。

此外，聚合数量越多，图标会按平方根增长，但最大不会无限大：

- `1 + 0.22 * sqrt(count - 1)`
- 再被限制到 `2.8` 倍以内

这样可以表达“这是聚合后的群体”，但不会遮满整张小地图。

### 建筑绘制

建筑没有做群聚，而是逐个绘制：

- 如果开启队伍染色，先画底色矩形。
- 再画白色 `uiIcon`。

建筑图标大小基于 `max(tilesize, block.size * tilesize) * buildingScale`，说明大建筑会天然更大。

## 筛选对话框是怎么实现的

单位和建筑筛选对话框都采用同一套交互模式：

- 顶部搜索框。
- 全选、清空、反选三个快捷按钮。
- 下方滚动网格列表。
- 每个条目是带图标的 `TextButton`，点击切换启用状态。

实现上很克制：

- 不自己维护复杂分页或虚拟列表。
- 只在搜索变化时重建显示列表。
- 提交时把名称列表写回 JSON 设置，再重建 id 缓存。

### 为什么缓存成 `boolean[]`

筛选对话框最终存的是名称列表，但绘制和可见性判断时用的是 `boolean[]`：

- 单位通过 `type.id` 直接索引。
- 建筑通过 `block.id` 直接索引。

这是明显的性能优化，因为频繁绘制时做字符串集合查询会更重。

## 内部子类分别做什么

### `HudMinimapOverlay`

封装了叠加层元素本身：

- `act()` 跟随原小地图 base 元素同步位置和大小。
- `draw()` 负责裁剪、变换、刷新缓存和绘制。

### `UnitCluster`

封装聚合后的单位群体：

- 记录类型和队伍。
- 记录质心坐标。
- 记录方向向量和回退朝向。
- 记录数量。

这是一个非常轻量的数据结构，没有额外继承和泛型负担。

## 与其他层级的关系

- 与上层 `betterminimap/`：上层负责入口和更新检查，这一层负责实际功能。
- 与 `resources/bundles/`：这里定义的设置项标题和按钮文字全部依赖 bundle。
- 与根目录 `build.gradle`：这个类最终会同时以 `.class` 和 `classes.dex` 形式进入发布包。
- 与 `dist/`：用户最终安装的 jar/zip 的核心价值几乎都来自当前类。

## 用一句话概括这一层

这一层就是“把 Mindustry 原版小地图变成更可读、更可配置、同时尽量不额外耗性能的增强显示系统”。
