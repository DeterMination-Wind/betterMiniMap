# `src/main/java` 目录详解

## 这一层在做什么

这一层是 Java 源码根目录，负责承载所有会被编译成 `.class` 的模组逻辑。它解决的是“模组到底做什么、什么时候做、如何与 Mindustry API 交互”这些问题。

当前源码都放在 `betterminimap/` 包下，说明项目规模还比较集中，没有拆成多个顶级包。

## 这一层的设计特征

### 1. 以 Mindustry 生命周期为主线

代码不是传统业务服务那种请求驱动，而是围绕 Mindustry 的客户端生命周期组织：

- 模组初始化时注册功能。
- 客户端加载完成时注入设置页和叠加层。
- 世界加载后重建可见缓存。
- 每帧更新时按间隔刷新设置和可见内容。

### 2. 以静态工具/特性类为主

项目没有复杂的对象图或依赖注入结构，而是采用静态方法和静态状态：

- `BetterMiniMapMod` 作为 Mindustry 要求的入口类。
- `GithubUpdateCheck` 作为独立的更新检查工具。
- `features/BetterMiniMapFeature` 作为核心功能中心。

这种结构对小型客户端模组非常实用：

- 初始化简单。
- 全局状态集中。
- 不需要额外框架支持。

### 3. 明确区分“入口”“配套功能”“核心功能”

- 入口类只负责挂接，不直接承载所有实现。
- 更新检查独立成文件，避免污染核心渲染逻辑。
- 小地图叠加层逻辑集中在 feature 类里。

## 与资源层的关系

这里的 Java 类大量依赖 bundle key，而不是写死中文或英文字符串。例如：

- 设置项标题通过 `@settings.betterminimap` 和 `setting.*` 读取。
- 单位筛选/建筑筛选弹窗标题、搜索提示、全选/清空/反选文字都从 bundle 中读取。

这说明 `java/` 虽然负责行为，但它故意把文案控制权交给 `resources/`。

## 与构建层的关系

这一层的类会经历两种输出形态：

- 普通 `.class`，供桌面版和通用 jar 使用。
- 通过 D8 转成 `classes.dex`，供 Android 加载。

所以这里的代码写法必须同时适配 Java 8 语法和两个运行端的装载方式。

## 与下一级包的关系

- `betterminimap/`：包含入口和配套工具。
- `betterminimap/features/`：包含真正的小地图渲染与设置逻辑。

可以理解为：

- 当前层负责声明“这是代码根”。
- 下一级包负责声明“这些代码属于 betterMiniMap 模组”。
