# `src/main/resources` 目录详解

## 这一层在做什么

这一层是运行时资源层。对于当前项目，它的核心价值不是图片、音频或数据表，而是本地化文本资源。

虽然目录里只有 `bundles/`，但这个层级仍然很重要，因为它承接了一个关键维护原则：用户可见文案不要硬编码在 Java 里。

## 为什么资源层对这个项目尤其重要

betterMiniMap 的功能不是后台逻辑，而是直接暴露给玩家的 UI 功能，所以会有大量用户能看到的文本：

- 设置分类标题。
- 各种设置项名称和说明。
- 单位/建筑筛选弹窗标题。
- 搜索提示语。
- 全选、清空、反选等操作按钮提示。

如果这些文本写死在代码里，会带来几个问题：

- 中英文切换困难。
- 修改文案要重新进代码逻辑文件，影响阅读。
- 后续加语言包时成本高。

当前项目把这些文本全都下沉到资源层，是一个非常标准也非常正确的做法。

## 资源层的构建行为

Gradle 会把这里的文件直接复制到输出资源目录，再打进 jar/zip。也就是说：

- Java 编译器不会处理它们。
- Mindustry 运行时会从资源包里读取 bundle。
- `BetterMiniMapFeature` 和 `BetterMiniMapMod` 在运行时通过 key 访问这些文案。

## 当前目录的下一级

- `bundles/`：Mindustry/Arc 的本地化 bundle 文件集合。

## 与其他层级的关系

- 与 `src/main/java/`：Java 层负责调用 key，资源层负责提供 key 对应文案。
- 与 `build.gradle`：资源文件会被纳入 `sourceSets.main.output`，最终参与打包。
- 与 `dist/`：最终发布物中 `bundles/bundle.properties` 和 `bundles/bundle_zh_CN.properties` 就来自这里。

## 这一层的边界

这里不负责：

- 何时显示某个设置项。
- 如何绘制小地图图标。
- 如何筛选单位或建筑。

它只负责让这些行为在 UI 上以合适语言呈现出来。
